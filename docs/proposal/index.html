Summary Problem Goals & Deliverables Schedule Resources

Neural texture compression (NTC) stores a material’s textures as a small table of learned features and a decoder network. These features and network weights are commonly kept in 16-bit floating point. We propose quantizing both with modern block scaling schemes such as microscaling (MX) formats. We will implement the system in a real-time renderer and evaluate it on the full Bistro scene, measuring texture memory, image quality after filtering and shading, and frame time across bit widths. We contribute a quantization scheme and quantization-aware training procedure that reduces the bits per stored value while keeping high quality images, and efficiently mapping the decoder to Tensor Core matrix hardware. We use a 16-bit system as our baseline.

Problem description

Textures account for a large part of GPU memory in rendering due to their large memory footprint. Neural texture compression addresses this issue by representing a material's textures with a small table of learned values and a small decoder network that reconstructs texel values per pixel at render time. NVIDIA reports that a 2048 by 2048 material with eight channels occupies 12 MB in conventional block-compressed formats and 2.5 MB in the neural format when decoded per sample (NVIDIA 2026). However, due to the increase in computation required per pixel, neural texture compression can reduce rendering performance by 20 to 30 percent (Panteleev 2025). Our work targets both sides; block scaled formats reduce the bits per stored value, while leveraging the high compute throughput of low-precision tensor core instructions in modern GPUs.

Recent work runs texture decoding on GPU matrix hardware (Belcour and Benyoub at Intel 2025), storing features as 8-bit integers with quantization-aware training (Fuijeda and Harada 2024) . Their system uses a fixed format for the learned features, and keeps the decoder in 16-bit floating point. To our knowledge, no prior system uses block-scale formats, variable bit-width, or decoder weight quantization. We aim to build upon this work and study the numerical representation of both learned features and decoder weights. Reducing the number of bits per stored value lowers memory usage, and we expect it to do so without significantly sacrificing image quality.

We will study the numerical representation of the learned values and decoder weights. Many existing quantization schemes use a fixed format for learned values and retain the decoder in 16-bit floating point. Our review has not identified a system that uses shared-scale block formats, varies the bit width, or quantizes decoder weights. By reducing the number of bits per stored value, we can reduce memory usage without significantly sacrificing image quality.

Lowering precision creates three challenges. First, at 4 or 6 bits per value, quality might suffer, so we must train with quantization in the loop to keep images accurate. Second, texture hardware cannot filter block scaled values, so our decoder must filter them. Third, the full scene must render in real time, which requires the data layout to match the GPU arithmetic units. We will evaluate all three in real time on a full scene.

Research questions

The evaluation will address the following questions:

  1. At equal memory usage, does block-scaled quantization of the learned table provide higher quality than uniform quantization or BC1 storage?
  2. What is the minimum bit width before errors become visible after shading?
  3. How does 8-bit integer quantization of the decoder affect quality and decoding time?
  4. What is the best decoder update granularity when rendering scenes in real-time?

Goals and deliverables

Our deliverables include a quantized compression system, a real-time renderer that uses it on a full scene, and an evaluation of block-scaled quantization against the non-quantized baseline at equal memory usage.

We will implement the compressor and decoder. The compressor will train the learned table and decoder while simulating each format's rounding behavior. The decoder will reconstruct values using each block's shared scale and evaluate the network on NVIDIA Tensor Cores, using matrix operations with a width of 16 values. The quantization scheme will support four block-scaled formats from the Open Compute Project's microscaling specification: MXINT8 and MXFP8, MXFP6, and MXFP4, and one NVIDIA proprietary format: NVFP4. As baselines, we will implement two quantization schemes and compare them at equal memory usage. The first uses uniform quantization at 8 and 4 bits, with one scale per table. The second stores values in BC1 format, following Belcour and Benyoub, to support texture hardware filtering.

The CUDA decoder will reconstruct each block, evaluate the network using Tensor Core instructions in 16-bit floating point or 8-bit integer arithmetic, and output material values for shading. We will integrate it into a real-time renderer, with all textures compressed by our system. The renderer will select a suitable level of detail per pixel and filter across neighboring values.

The results will include a comparison of the original textures for each format with analysis of memory usage and frame time as the format changes.

Stretch goals

Our stretch goals include four extensions: a decoder that returns four neighboring texture values in one evaluation, subject to an initial literature review confirming its novelty; automatic bit allocation that assigns fewer bits to texture channels that tolerate more error; measurements on a second GPU, preferably one with reported native Tensor Core support for 4-bit and 6-bit formats; and release of the evaluation scripts as an open benchmark for small networks evaluated per pixel, a workload not covered by SPECviewperf 15, 3DMark or LumiBench.

Feasibility and risks

Our team has experience with microscaling formats. Training requires fitting a small model to each material, and prior work provides a tested baseline and renderer design. We expect decoder quantization to have a limited effect on decoding time because prior work reports nearly constant decoding time across network widths when using matrix hardware. The main expected benefit is reduced memory usage. If the full-scene renderer is delayed, we will demonstrate the system on the smaller FlightHelmet model.

Resources

The project requires one NVIDIA RTX GPU with Tensor Cores; the model remains to be specified. A second GPU is needed only for the stretch goals. We will implement the decoder in CUDA and the compressor in PyTorch. The open-source tiny-cuda-nn library will serve as a reference for the decoder implementation.

We will use material texture sets from Poly Haven and ambientCG, the FlightHelmet model, and the Bistro scene, following prior work. We will compare the scope of our evaluation with SPECviewperf 15, 3DMark and LumiBench.
